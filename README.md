# موقع شركة تشطيبات وديكورات — صفحة هبوط + لوحة تحكم + CRM

مشروع كامل قابل للتشغيل: صفحة هبوط عربية RTL عالية التحويل، ولوحة تحكم عربية حقيقية لإدارة المحتوى وطلبات العملاء، وقاعدة بيانات وتتبع تحويلات.

> **تنبيه:** اسم الشركة وأرقام التواصل والصور الحالية **بيانات تجريبية** واضحة (شريط «نسخة تجريبية» يظهر أعلى الموقع). الصور رسوم معمارية توضيحية مولّدة برمجيًا وليست مشاريع فعلية. استبدلها كلها من لوحة التحكم ثم أوقف «وضع النسخة التجريبية».

---

## التشغيل السريع

المتطلبات: Node.js 22.13 أو أحدث (يُفضَّل أحدث نسخة LTS). لا يحتاج Python ولا أدوات Visual Studio.

```bash
npm install
cp .env.example .env        # ثم املأ SESSION_SECRET و ADMIN_EMAIL و ADMIN_PASSWORD
npm start
```

- الموقع: `http://localhost:3000`
- لوحة التحكم: `http://localhost:3000/admin`

يُنشأ حساب المدير تلقائيًا عند أول تشغيل من `ADMIN_EMAIL` و`ADMIN_PASSWORD` (10 أحرف على الأقل، حروف وأرقام). أو يدويًا في أي وقت (ويُستخدم أيضًا لإعادة تعيين كلمة المرور):

```bash
npm run create-admin -- you@company.com "StrongPass2026" "اسمك"
```

الاختبارات: `npm test` (10 اختبارات تكامل للنموذج والصلاحيات والمحتوى والإعدادات).

## التقنيات

| الجزء | الاختيار | السبب |
|---|---|---|
| الخادم | Node.js + Express | خفيف وسهل الاستضافة |
| قاعدة البيانات | SQLite المدمجة في Node.js (`node:sqlite`) | ملف واحد بلا خدمة خارجية ولا أدوات بناء، يكفي لآلاف الطلبات؛ قابل للنقل إلى PostgreSQL |
| الواجهة | EJS (عرض من الخادم) + CSS/JS بلا مكتبات | سرعة تحميل عالية وفهرسة كاملة لمحركات البحث |
| لوحة التحكم | تطبيق صفحة واحدة بـ JavaScript خالص | لا خطوة بناء ولا تبعيات أمامية |
| الصور | sharp | ضغط وتحويل تلقائي إلى WebP بمقاسين (800 و1600) وحذف بيانات EXIF |
| الخطوط | Alexandria + IBM Plex Sans Arabic | مستضافة محليًا (لا اعتماد على Google Fonts) |

## نموذج طلب المعاينة — كيف يعمل

1. تحقق في المتصفح (رسائل عربية تحت كل حقل) ثم تحقق كامل في الخادم.
2. رقم الجوال يُطبَّع إلى الصيغة الدولية (يقبل الأرقام العربية ٠-٩، والمسافات، و+966 أو 05…). الدولة تُضبط من الإعدادات: السعودية، الإمارات، الكويت، قطر، البحرين، عُمان، مصر.
3. الحماية من الرسائل المزعجة: حقل مخفي (Honeypot)، رفض الإرسال الأسرع من ثانيتين، حد 5 طلبات لكل جهاز كل 10 دقائق، و**Cloudflare Turnstile** اختياري.
4. منع التكرار: مفتاح فريد لكل نموذج (الضغط المزدوج أو إعادة المحاولة لا ينشئ طلبًا ثانيًا)، ونفس الرقم خلال 10 دقائق لا ينشئ طلبًا جديدًا.
5. **رسالة النجاح لا تظهر إلا بعد أن يؤكد الخادم حفظ الطلب في قاعدة البيانات** ويعيد رقم الطلب. عند أي فشل تظهر رسالة خطأ واضحة مع بديل واتساب.
6. يُسجَّل مع الطلب: القناة المستنتجة، UTM، gclid/gbraid/wbraid/fbclid، صفحة الهبوط، المُحيل.

حالات الطلب: جديد ← تمت محاولة التواصل ← مؤهل ← تم إرسال عرض سعر ← تم التحويل إلى عميل / غير مؤهل. كل تغيير حالة يُسجَّل في سجل الطلب مع اسم الموظف.

**إشعار فوري بالطلبات الجديدة (اختياري):** ضع رابط Webhook في `LEAD_WEBHOOK_URL` (Make أو Zapier أو n8n) لإرسال الطلب إلى بريدك أو واتساب أو Slack لحظة وصوله.

## تتبع التحويلات (GA4 / GTM / Google Ads)

من **الإعدادات ← التتبع والحماية**:

- **مع GTM (الموصى به):** ضع `GTM-XXXXXXX` فقط. الموقع يرسل أحداث `dataLayer` التالية، وتنشئ الوسوم والمشغلات داخل GTM:

| الحدث | متى | بيانات مرافقة |
|---|---|---|
| `generate_lead` | **بعد حفظ الطلب فعليًا فقط** (وليس عند الضغط على الزر) | `lead_id`, `service`, `property_type` |
| `whatsapp_click` | فتح رابط واتساب (لا يعني أن رسالة أُرسلت) | `click_location` |
| `phone_click`, `cta_click` | النقر على الاتصال / أزرار طلب المعاينة | `click_location` |
| `form_start`, `form_error` | بدء التعبئة / فشل التحقق | `error_fields` |
| `project_view` | فتح تفاصيل مشروع | `project_title` |

   استخدم `lead_id` كـ **Transaction ID** في وسم تحويل Google Ads لمنع احتساب التحويل مرتين.
- **بدون GTM:** ضع معرف GA4 و/أو `AW-XXXXXXXXX` مع تسمية تحويل «طلب معاينة» و«نقرة واتساب»، وسيُرسل الموقع الأحداث والتحويلات مباشرة عبر gtag.
- إذا أضفت داخل GTM وسومًا لجهات أخرى (Meta Pixel، TikTok…) أضف نطاقاتها إلى `CSP_EXTRA_SOURCES` في `.env`.

## SEO

عرض من الخادم بالكامل، `lang="ar" dir="rtl"`، عناوين هرمية (H1 واحد)، Title/Description/OG قابلة للتعديل، رابط canonical، بيانات منظمة `HomeAndConstructionBusiness` و`FAQPage`، `sitemap.xml` و`robots.txt` تلقائيان، صور WebP متجاوبة بـ `srcset` وتحميل كسول ونصوص Alt.

**الموقع يمنع الأرشفة افتراضيًا** (لأن البيانات تجريبية). بعد النشر على النطاق النهائي: اضبط «رابط الموقع الأساسي» وفعّل «السماح لمحركات البحث بالأرشفة».

## الأمان

كلمات المرور bcrypt، جلسات في قاعدة البيانات بكعكة HttpOnly + SameSite=Strict (+Secure في الإنتاج)، قفل الحساب 15 دقيقة بعد 5 محاولات فاشلة، حماية CSRF (ترويسة مخصصة + فحص Origin)، Helmet وسياسة أمان محتوى بـ nonce، تحقق من كل المدخلات في الخادم، حماية تصدير CSV من حقن الصيغ، عناوين IP تُخزَّن مُجزّأة (hash) فقط، والمفتاح السري لـ Turnstile لا يُعاد أبدًا للواجهة.

## النشر

**على خادم VPS (Ubuntu):**

```bash
npm ci --omit=dev
NODE_ENV=production pm2 start server.js --name finishing-site
```

ضع Nginx أمامه مع شهادة SSL (Let's Encrypt) واجعل `TRUST_PROXY=1`. انسخ مجلدي `data/` و`uploads/` احتياطيًا بانتظام — فيهما كل الطلبات والصور.

**Docker:**

```bash
docker build -t finishing-site .
docker run -d -p 3000:3000 --env-file .env -v $(pwd)/data:/app/data -v $(pwd)/uploads:/app/uploads finishing-site
```

**منصات مثل Railway / Render / Fly.io:** تعمل مباشرة، بشرط ربط **قرص دائم (Persistent Volume)** بمساري `data` و`uploads` (عبر `DB_PATH` و`UPLOAD_DIR`)، وإلا ستُمسح الطلبات مع كل إعادة نشر. الاستضافات الخالية من الحالة (Vercel/Netlify Functions) غير مناسبة لـ SQLite.
